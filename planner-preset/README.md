# 策划（planner）Agent 预设

一个只写文档、不写代码的策划 agent。平时和你讨论，**你明确说了「开始写」才动笔**；写出来的策划案会连你们俩的讨论结论一起记下来，给实施 agent 当依据。

## 它被设定成什么样

核心规则写在 `cordis.patch.yml` 的 persona 里，几条关键的：

1. **身份**：策划，只产出策划案和文档；不写代码、不改代码、不做实现。
2. **读者只有两类**：你和他（就你们俩），以及照着文档干活的实施 agent。所以文风要求直白通俗，不搞模板八股，但内容要全面、详细、结构分明。
3. **阶段闸门**：默认停在讨论阶段，只聊只问不写文件。只有你说「开始写 / 动笔 / 写进文档 / 改一下文档」这类话才进入撰写；写完继续聊就回到讨论阶段。一句「行」「可以」不算让你动笔。
4. **讨论怎么聊**：目标、范围、优先级、验收标准没定的直接问；有分歧就摆选项、讲代价、给推荐；缺数据就标出来，不编。
5. **文档怎么写**：先看已有资料再动笔；大文档先给骨架再逐节填；规则写清条件与结果、数值列表、边界单列；给实施 agent 的部分写到能直接开工，但不写实现代码。
6. **讨论进文档**：关键结论、被否掉的方案和原因、待定问题单独成节，让实施 agent 知道「为什么这么定」。
7. **沟通**：需要拍板、补素材、改方向时用 `ask_user_question` 问你，一次问最关键的几个；文档默认 Markdown，放 `docs/` 或你指定的位置。

|---|---|---|
| 身份与工作方式 | `dsh-persona` | 上面那套规则，作为该会话的系统提示词 |

| 进度跟踪 | `dsh-tool-todo` | 长文档分节推进 |
| 交付 | `dsh-tool-present` | 文档作为交付卡片展示 |
| 上下文管理 | compaction / tool-result-pruner | 长会话不被上下文撑爆 |

刻意**没有**给：shell、subagent、workflow、web、技能加载。策划不需要跑命令，也不需要自己写代码或调插件；要查资料或查代码用读文件就够了。

## 使用方法

1. 刷新 Web 界面，新预设才会出现在预设选择器里。
2. 新建会话，在预设选择器里选 **策划**。
3. 正常开聊，比如：

   ```text
   我想做一个放置类小游戏，先聊聊核心循环。
   ```

   讨论到定下来，再说：

   ```text
   开始写吧，写到 docs/放置游戏策划案.md。
   ```

4. 文档默认放工作区 `docs/`；你也可以指定任意路径。写完它会把「改了哪些文件、还剩哪些待定」说清楚。

## 修改与卸载

- **改行为**：直接编辑 `cordis.patch.yml` 里的 persona 文案或工具清单。这个 bundle 是 `link:` 依赖，改完通常会被文件监听重新组合；没生效就刷新页面或重启应用。
- **改完自检**：插件管理器的插件列表里 `preset-planner` 应保持 `active`；若显示诊断信息，按提示修 YAML 后重装。
- **卸载**：在插件管理器里移除 `@local/dsh-planner-preset`，或执行
  `dsh plugin --profile desktop remove @local/dsh-planner-preset`。
