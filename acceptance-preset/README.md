# 项目验收（acceptance）Agent 预设

一个只做验收、不改项目的 agent。你把项目和文档交给它，它逐项对照「文档说的」和「实际做到的」，把问题定位到具体模块/文件，最后给结论与问题清单。

**它不修改、不创建、不删除项目里的任何文件**：预设里没有 `write` / `edit` 工具；shell 只用于跑只读检查和测试，涉及写入的操作必须先问你。

## 它被设定成什么样

核心规则写在 `cordis.patch.yml` 的 persona 里：

1. **先定依据**：先找全文档（README、需求/设计、验收标准、接口/配置、部署、CHANGELOG、AGENTS.md/CLAUDE.md）。文档矛盾时按「验收标准 > 需求/设计 > README > 其他」排序，并把矛盾本身记为问题。
2. **可判定**：每条要求拆成能判「通过/不通过」的验收项，写进 todo；标准不清或范围不清时先问你。
3. **先静后动**：先读代码找落点（入口、路由、命令、配置键、测试），不够再跑测试/类型检查/启动；运行时优先只读命令，可能写文件的先问，或放到临时目录/项目副本里跑。
4. **证据说话**：每个结论都指到 `路径:行号`、命令输出或测试结果；找不到实现再找配置/动态注册/生成代码，确认不了就写「待确认」。
5. **问题可定位**：每条问题记录所属部分、对应文档条目、类别、严重级别、现象与证据、影响和建议修法；只说建议，不动手。
6. **结论分级**：通过 / 有条件通过 / 不通过；证据不足不硬下「通过」。
7. **报告默认在对话里**：结论、覆盖率、问题清单、未覆盖项、文档缺口、优先处理建议。只有你明确要求保存时，才新建一份报告文件，且不碰任何已有文件。

## 预设包含什么

| 能力 | 插件 | 说明 |
|---|---|---|
| 身份与验收流程 | `dsh-persona` | 上面那套验收规则，作为该会话的系统提示词 |
| 工作区指令 | `dsh-agent-instructions` | 读取项目里的 `AGENTS.md` / `CLAUDE.md` |
| 时间上下文 | `dsh-time-context` | 报告里能写准日期 |
| 文件读取 | `dsh-tool-fs` | 只给 `read` / `read_image`；**`write` / `edit` / `apply_patch` 全部关闭** |
| 目录与内容检索 | `dsh-tool-fs-search` | `glob` / `grep`，找文档与代码落点 |
| 命令验证 | `dsh-tool-bash` / `dsh-tool-pwsh` | Windows 用 pwsh，其他平台用 bash；受 persona 红线约束 |
| 长任务 | `dsh-tool-jobs` | 测试、构建等放到后台，避免阻塞 |
| 技能加载 | `dsh-skill-filesystem` + `dsh-tool-skill` | 项目自带技能（如 Office、项目调查）可按需加载 |
| 澄清问题 | `dsh-tool-ask-user` | 范围、标准、是否允许运行命令 |
| 进度跟踪 | `dsh-tool-todo` | 按模块维护验收清单 |
| 大项目并行 | `dsh-tool-subagent` / `workflow` | 按目录分片核验后汇总 |
| 联网核对 | `dsh-tool-web` | 需要核对标准、版本或外部文档时使用 |
| 交付 | `dsh-tool-present` | 报告保存成文件后作为卡片展示 |
| 上下文管理 | compaction / tool-result-pruner | 长验收不被上下文撑爆 |

刻意**没有**给：文件写入/编辑工具、依赖安装、git 写操作、plan mode、goal、schedule。验收只产出结论和问题记录，不产出代码改动。

## 使用方法

1. 刷新 Web 界面，新预设才会出现在预设选择器里。
2. 新建会话，在预设选择器里选 **项目验收**。
3. 把验收对象和依据文档给它，例如：

   ```text
   对 D:\projects\my-app 做整体验收，依据是 docs/需求说明.md 和 docs/验收标准.md。
   不要改任何文件；不确定的地方先问我。
   ```

   它会先确认版本/范围，再按模块列出验收清单、逐项核验，最后给出结论和问题清单。

4. 想追加深度验证时可以指定：

   ```text
   把测试和构建也跑一遍，但只允许只读命令；需要写文件先问我。
   ```

## 安全说明

- 「不改文件」有两层：文件工具层面已经禁用写入；shell 层面靠 persona 红线约束（只跑只读命令、有副作用先问、前后核对 `git status`）。
- 想要**物理层面**的保证，把会话权限预设切到**只读**：那时 shell 的写入会被沙箱直接拒绝，验收过程只能读和执行只读检查。
- 默认不生成报告文件；报告先给在对话里。要落盘时只新建 `docs/验收报告-<日期>.md`（或你指定的路径），不修改已有文件。
- 联网只用于核对公开标准/版本/文档，不用于修改项目。

## 调整与卸载

- **改验收规则或报告格式**：直接编辑 `cordis.patch.yml` 里的 persona 文案。这个 bundle 是 `link:` 依赖，改完通常会被文件监听重新组合；没生效就刷新页面或重启应用。
- **加/减工具**：改 `plugins` 列表。例如去掉 `tool-web` 就完全不能联网；去掉 `delegation` 组就不会自动拆 subagent。
- **卸载**：在插件管理器里移除 `@local/dsh-acceptance-preset`，或执行
  `dsh plugin --profile desktop remove @local/dsh-acceptance-preset`。
